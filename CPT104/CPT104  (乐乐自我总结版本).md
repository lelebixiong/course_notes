#week3

**Process Synchronization 进程同步**
PS的任务
	 协调进程的执行, 使两个进程无法同时访问相同的共享数据和资源

**Concurrent Processing 并发进程**
Concurrent access(对数据的共享访问)可能会导致数据不一致

**Race condition争用条件**
多个进程同时访问和操作共享数据的情况, 共享数据的最终值取决于最后完成的过程

为了防止争用条件, 必须同步并发过程

每个(并发)线程/进程都有一个代码段, 成为"关键部分(CS)", 用于访问共享数据 





临界区(critical section)
	 临界区即是会访问共享资源的代码区
			  共享的对象:
				   如果对象是动态分配的, 则每个线程都需要一个指向他的指针
				   如果~是静态分配的, 线程只需要通过全局变量名引用它, 编译器会计算相应的地址

	 临界区的三个原则
		  互斥(mutual exclusion): 如果已有进程在临界区执行, 其他进程不能再临界区执行. 这里讲的都是写作进程
		  前进(Process): 如果没有进程在临界区, 其他进程应该被允许进入临界区
		  有限等待(bounded waiting): 进程做出进入临界区的请求后, 其他进程进入临界区的次数是有上限的, 进程发出请求后等待允许的时间有限

	 处理临界区的两种内核:
		  抢占式(preemptive kernel): 允许进程在内核模式下运行时被抢占
		  非抢占式(non-preemptive kernel): 进程在内核模式运行时不会被抢占, 不会产生竞争




#week4-5

程序由CPU执行和I/O等待组成
	 程序据此也可分为CPU繁忙型和I/O等待型
		  CPU调度是一种机制, 用于选择接下来必须执行哪个进程并将CPU分配给该进程
		  调度程序负责将进程的一种状态转移到另一种状态

Long-Term Scheduler在创建新进程时执行. 决定是否将进程添加到当前处于活动,状态的进程集
Short-Term Scheduler是下一步要执行哪个就绪进程的实际决策
Medium-Term Scheduler 是交换功能的一部分

Dispatcher 是操作系统的一个模块, 它将进程从就绪队列中移除并发送给CPU完成

CPU调度策略
	 preemptive scheduling 抢占式
		  正在运行的进程会被打断, 然后下一个高优先级的进程会进入, 被打断的程序会返回准备队列, 等待未来重新调用
	non- preemptive scheduling 非抢占式
		 正在运行的进程不会被打断, 下个进程需要等待这个进程完成CPU周期
		 当前运行的进程会一直占用CPU知道它主动放弃使用

调度发生在这4种情况下:
	 进程从运行转为就绪
	 从运行转为等待(因为I/O请求或wait()等待)
	 从等待转为就绪(IO完成)
	 终止进程

Scheduling Criteria 调度准则
Arrival Time:
	 进程到达时间: 进程到达就绪对列的时间
Completion Time:
	 进程完成时间: 进程运行完毕结束的时间点
Burst Time(区间时间):
	 进程完整运行完所花费的时间
Turnaround Time(周转时间):
	 从进程提交到进程完成的时间段(包括等待进入内存, 在就绪队列中等待, 在CPU上执行和I/O执行)
		  周转时间= 等待时间+执行时间 = 结束时间 - 进入队列时间
Waiting Time(等待时间):
	 在就绪队列中等待的时间
		  等待时间 = 终止时间 - 到达时间 - 持续时间

**公式!!**
每个进程的等待时间(Waiting Time) = 每个进程的周转时间 - 区间时间
每个进程的周转时间(Turnaround Time) = 每个进程完成时间 - 每个进程的到达时间

   #week6死锁

每个进程使用资源时as follows: Request -> Use -> Release

死锁可以定义为永久阻止一组争用系统资源的进程

死锁的四个特征(也是死锁产生的必要条件)
	 互斥 mutual exclusion
	 占有并等待 hold and wait
	 非抢占 no preemption 
	 虚幻等待 circular wait

If  a graph contains  no cycles--> no deadlocks(当图中没有环则代表没有死锁)
If a graph contains a cycle-->
	 if only one instance per resource type, then deadlock;
	 if several instances per resource type, possibility of deadlock
(如果存在环:
    一个资源只有一个实例, 则有死锁;
    一个资源有多个实例, 则可能有死锁
)



避免死锁的相关知识:
	 max needs: 一个进程最大可能需求的资源数量
	 available resources: 现未被分配的资源
	 need: 进程需要的资源数量
	 allocation: 已被分配给进程的资源

#### 步骤 2: 判断是否安全

- 当前可用资源: A: 3, B: 3, C: 2

#### 进程安全性检查：

1. **检查 P0**: 所需 (7, 4, 3) > 可用 (3, 3, 2) -> 不满足
2. **检查 P1**: 所需 (1, 2, 2) ≤ 可用 (3, 3, 2) -> 满足，执行 P1

3. **检查 P0**: 所需 (7, 4, 3) > 可用 (5, 3, 2) -> 不满足
4. **检查 P2**: 所需 (6, 0, 0) > 可用 (5, 3, 2) -> 不满足
5. **检查 P3**: 所需 (0, 1, 1) ≤ 可用 (5, 3, 2) -> 满足，执行 P3
    - 执行 P3 后，资源释放：可用 (5, 3, 2) + (2, 1, 1) = (7, 4, 3)
6. **检查 P0**: 所需 (7, 4, 3) ≤ 可用 (7, 4, 3) -> 满足，执行 P0
    - 执行 P0 后，资源释放：可用 (7, 4, 3) + (0, 1, 0) = (7, 5, 3)
7. - **检查 P1**: 所需 (1, 2, 2) ≤ 可用 (7, 5, 3) -> 满足，执行 P1
    - 执行 P1 后，资源释放：可用 (7, 5, 3) + (2, 0, 0) = (9, 5, 3)

MMU内存管理单元
	 进程使用虚拟地址(virtual address)访问内存
		 OS(操作系统)(硬件( MMU))将虚拟地址转换为物理RAM地址

		 将虚拟地址转换为物理地址

逻辑地址(虚拟地址)

指令和数据与存储器的绑定
	 编译(Compile Time): 将绝对地址编译进程序

Storage Management   Mass-Storage Systems
	 ### **辅助存储（Secondary Storage）**

辅助存储是**永久保存数据**的设备，特点如下：

- **永久保存数据**：即使断电，数据也不会丢失。
    
- **比内存慢**：访问速度不如主存（如RAM）。
    
- **更便宜且容量更大**：单位价格比内存低，通常用于存储大量数据。
